# 富龙地图 MVP 当前范围

更新：2026-09-28。

这是当前实现的执行入口。它描述“现在应当做什么”；分阶段未来计划见
[MVP 路线图](mvp-roadmap.md)，逐次用户修正和自动化证据见
[描摹验收记录](trace-pilot-review.md)。

## 产品目标

先完成富龙，再以相同数据契约接入其他雪场：

- 用一张结构忠于用户参考图的完整雪道图承载搜索、详情和路线规划。
- 每条已发布雪道都有文字、视频匹配、来源和明确的缺失/冲突状态。
- 路线只使用审核过的有向连接，并在同一张图上高亮实际使用的分段。
- 桌面端以地图为主、详情为辅；移动端可搜索、点选并避免横向溢出。

视觉可以重做，但山体的相对结构、分岔、汇合和交通设施不能凭审美重排。
这张图不是测绘图、实时开放状态产品或现场导航保证。

## 当前基线

GitHub Pages 根路径现在发布结构版 MVP；`/?prototype=fulong-trace` 是本地
增强校准工作台：

- 使用用户提供的 3631 × 2560 WEBP 原始像素坐标；
- 生产页使用独立线稿；本地工作台额外支持原图和叠加校准；
- 绘图、点击、选中和路线演示复用同一批候选分段；
- 提供全图、山顶、中央/公园、西侧、东侧和初学区视图；
- 记录 65 个图示分段、35 组雪道编号、3 个参考要素和 9 条交通设施；
- 51 个分段仍排除在有向路线规划之外。

用户已表示当前雪道整体结构没有重大问题，并进一步授权将线稿作为 Pages
首页。发布结构预览不代表内容 MVP 已完成，也不把候选几何升级为可通行路线。

已纳入当前基线的用户修正包括 C5/C7、A7/A8 分岔、B11/B13/B15 回弯、
C1—岚山餐厅连接、L3/L5/L7 山顶汇合、L5 中途下客站、统一线宽与透视层。
不要在本文件重复每一轮坐标和截图；需要追溯时查验收记录。

## 当前不做

- 不把候选几何直接当成现场导航或完整通行图；
- 不把 33 条旧参数记录当作全图固定上限；
- 不从临时标注颜色或编号推断难度；
- 不从视觉相交、距离或共享端点推断滑行方向；
- 不把“可能取消”“去年开放”等用户报告写成实时运营事实；
- 不把缺失视频渲染成推荐视频；
- 不提交或发布本地高清原图，除非版权边界另有明确结论。

## 验收门槛

1. **来源一致**：地图引用的源图身份、尺寸、坐标系和使用边界见
   [校准契约](research/fulong-reference-calibration.md)。
2. **几何可复核**：分段、端点、分岔和共享节点能在同坐标叠加中检查；
   历史修正不能只存在于聊天记录。
3. **数据可追溯**：用户可见字段绑定来源、季节和
   `VerificationState`，缺失与冲突显式显示。
4. **路线有向**：只有明确审核的有向边进入发布图；无法证明时返回无路线。
5. **交互闭环**：搜索/点图 → 雪道详情 → 视频证据 → 路线规划使用同一个
   稳定雪道 ID。
6. **发布边界清楚**：生产地图、候选描摹、实时开放和现场导航在界面上不混淆。

## 下一步实现顺序

### 1. 冻结描摹基线

为当前候选数据建立一个可回溯的基线版本，保留源图、用户修正和关键截图。
后续几何改动必须带有新的来源说明和针对性回归测试。

### 2. 建立发布数据契约

实现并逐步替换原型单例的数据边界：

- `Resort`、`Trail`、`TrailLocation`、`MapNode`；
- `UphillTransport`、`TransportStation`；
- `SourceSnapshot`、字段级 `Claim` 和 `VideoMatch`；
- 有向 `RouteSegment`、`RoutePlan` 和季节化 `OperatingSnapshot`。

每个用户可见字段至少支持 verified、unverified、missing、conflicting、
stale 或 link-only 之一。

### 3. 先做一条内容纵切

以 B10、B11、B12、B13、B15 为第一批：

- 名称/编号、难度或明确未知；
- 简介、入口/出口和已知连接；
- 来源日期和证据链接；
- trail-specific、zone-level、resort-level 或 missing 的视频状态。

详情面板先接这批数据，确认契约稳定后再扩展其余雪道。

### 4. 接入审核后的路线

只提升已复核的有向边；交通设施保留类型和上下站语义。方向待定的线仍可
显示，但不进入发布路线图。至少完成一条端到端、可解释的富龙示例路线。

### 5. 连接用户交互并准备发布

把搜索、地图点选、详情、视频和起终点选择收敛成一个工作流；之后再做编辑
数据层、运营快照、无障碍/性能检查和生产替换。第二个雪场只能通过
`resortId` 数据包接入，不能复制一套富龙逻辑。
