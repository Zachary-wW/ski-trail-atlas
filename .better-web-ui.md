## Design Context

### Users
Primary users are skiers researching Fulong Ski Resort, especially people who know a Trail name/code and want to understand where it sits on the mountain, how difficult it is, and what evidence supports the published information. Desktop should reward spatial exploration; mobile should make search and Trail lookup immediately usable.

### Brand Personality
Precise, editorial, alpine. The product should feel like a serious independent mountain atlas made by people who ski, not a travel marketplace, resort brochure, or SaaS dashboard. Copy should be calm, concise, and evidence-aware.

### Aesthetic Direction
Use high-end editorial cartography as the default visual language: strong typography, intentional whitespace, hairline rules, map-first composition, restrained surfaces, and a small number of meaningful accent colors. References include the calm editorial quality of lieflat-charts and the polished interaction sensibility of oil-motion. Anti-reference: generic AI dashboards, card grids, excessive rounded pills, gradients used as decoration, and visual hierarchy built from containers instead of typography/space.

The design exploration may include both light and dark directions, but the production choice should preserve excellent map legibility and long-session comfort. Trail difficulty color must communicate meaning rather than decorate the UI.

### Implementation Defaults
Existing stack: React 19 + TypeScript + Vite, with hand-authored vanilla CSS and no component library. Preserve that stack during design exploration unless a later implementation decision explicitly changes it. Existing URL-based Trail state and bilingual EN / zh-CN behavior are product constraints. Prototype work should remain isolated from production routes until a direction is selected.

### Design Principles
1. Let the Panorama Map carry the page; UI chrome should frame it, not compete with it.
2. Establish hierarchy with typography, spacing, and scale before adding borders, cards, or color.
3. Treat Trail data as atlas annotation: compact, scan-friendly, and spatially related to the selected Trail.
4. Use color semantically for Trail difficulty, selection, evidence state, and interaction feedback; keep the rest restrained.
5. Never make visual polish imply geographic certainty. Concept geometry, unverified topology, and verified data must remain distinguishable.
